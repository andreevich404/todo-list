# To-Do List — лабораторная работа №10

Vue 3 + TypeScript: личные задачи, начало и дедлайн, приоритеты, метки,
пять представлений списка, учебные аккаунты и две темы.

- ФИО: Толкачев Иван Андреевич
- Группа: ФИТ-241
- Node.js: **v24.22.0**
- [Опубликованное приложение](https://andreevich404.github.io/todo-list/)

## Установка и команды

```sh
npm ci                # установка по package-lock.json
npm run dev           # сервер разработки
npm run type-check    # типы приложения, Vue-шаблонов и конфигурации Vite
npm run lint          # ESLint без ошибок и предупреждений
npm run lint:fix      # явное автоисправление ESLint
npm run format        # форматирование Prettier
npm run format:check  # проверка форматирования
npm run check         # все статические проверки без изменения файлов
npm test              # домен, сценарии, репозитории, Pinia, маршруты и старые данные
npm run build         # check, затем сборка Vite в dist/
npm run preview       # локальный просмотр сборки
```

`vue-tsc` проверяет приложение и шаблоны, `tsc` — конфигурацию Vite.
Vite собирает приложение, но не проверяет типы. `build` останавливается при
ошибке типов, ESLint или Prettier. GitHub Actions запускает тесты и сборку
перед публикацией в Pages. Hash-маршруты поддерживают прямые ссылки и перезагрузку.

## Архитектура

- `src/domain/` — модель, валидация, сортировка, поиск и отбор по датам.
  Обычный TypeScript; входные списки не изменяются, текущая дата передаётся аргументом.
- `src/application/` — загрузка, создание, изменение, выполнение и удаление задач.
  Сценарии получают пользователя снаружи и работают через контракт `TodoRepository`.
- `src/infrastructure/` — реализации контракта для `localStorage` и памяти,
  чтение старых записей и изоляция задач пользователей.
- Компоненты, страницы и `src/stores/` — формы, фильтры, ошибки и реактивное
  состояние. Pinia вызывает сценарии; задачи плагином Pinia не сохраняются.

Зависимости направлены от UI и адаптеров к сценариям и домену. Домен и сценарии
не импортируют Vue, Pinia, браузерные API или конкретные репозитории.

Репозиторий выбирается только в `src/setup/todo.ts` и передаётся сервису,
который доступен Pinia через Vue provide/inject. По умолчанию подключён
`createLocalStorageTodoRepository`. Для временного хранения замените его
в этом месте на `createMemoryTodoRepository()` из `src/infrastructure/memoryTodoRepository.ts`.
Сценарии и компоненты менять не нужно; память очищается при перезагрузке.

## Даты, приоритеты и представления

Для создания достаточно названия. В блоке «Даты, приоритет и метки» можно
независимо указать начало и дедлайн, выбрать приоритет 0–3 и ввести метки
через запятую. Приоритет по умолчанию — 0, меток нет. Пустые метки и повторы
удаляются, регистр меток учитывается. Неверные даты, обратный порядок дат
и нецелый приоритет вне 0–3 отклоняются формой и сценариями; равные даты допустимы.

Даты сохраняются строками ISO 8601 в UTC. Форма и список показывают местное
время браузера. «На сегодня» и «Грядущие» используют только дедлайн и местные
календарные границы; неделя — с понедельника по воскресенье, включая прошедшие дни.

Во всех представлениях порядок: невыполненные → выполненные, приоритет по убыванию,
дедлайн по возрастанию, начало по возрастанию, id по возрастанию.
На каждом уровне задачи без соответствующей даты идут после задач с датой.
Приоритеты обозначены цветом и текстом: низкий, обычный, высокий, срочный.

| Вкладка     | Задачи                                                                                                    |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Поиск       | Невыполненные; название и выпадающий фильтр меток применяются совместно. «Все метки» снимает ограничение. |
| Все         | Все задачи пользователя.                                                                                  |
| На сегодня  | Дедлайн сегодня; выполненные включаются отдельным чекбоксом.                                              |
| Грядущие    | Дедлайн в текущей неделе; выполненные включаются отдельным чекбоксом.                                     |
| Выполненные | Выполненные без ограничения по датам.                                                                     |

Оба чекбокса изначально выключены. Вкладки доступны по Tab, стрелкам влево/вправо,
Home и End. Модалка сохраняет фокус, Esc и возврат к кнопке вызова.

## Прежние данные и проверка

Ключ и формат `todo.store` сохранены: общий список `tasks` с `userId` и счётчик
`nextId`. Репозиторий читает задачи лабы №9, добавляя отсутствующие поля:
приоритет 0, метки `[]`, даты отсутствуют. При следующей записи сохраняется
совместимый формат с новыми полями. Другие пользователи не затрагиваются;
повторное чтение не добавляет копий и не возвращает удалённые задачи.
Повреждённые записи отбрасываются, некорректные новые поля получают defaults.
При ошибке записи интерфейс сообщает о ней и не закрывает форму как успешно сохранённую.

Аккаунты и вход по-прежнему сохраняет `pinia-plugin-persistedstate` под ключом
`todo.users`, тема — под `theme`. Двойной записи задач нет. Авторизация учебная;
используйте только вымышленные адреса и пароли.

1. В том же браузере и по прежнему адресу откройте приложение после обновления:
   аккаунт и задачи лабы №9 остаются; во вкладке «Все» у старых задач низкий приоритет.
2. Создайте задачу только по названию, затем задачу с датами, приоритетом и метками.
   Проверьте редактирование и ошибку дедлайна раньше начала.
3. Проверьте пять вкладок, оба чекбокса, совместный поиск по названию и метке.
   Начало без дедлайна не включает задачу в календарные представления.
4. Удалите задачу и перезагрузите страницу: она не возвращается, новые поля сохраняются.
5. Выйдите, создайте второго учебного пользователя и войдите: чужих задач и меток нет.
   После повторного входа первый пользователь видит свои задачи.
6. Откройте `/#/todo` гостем — guard отправляет на вход. `/#/about` доступна всем.
   Проверьте перезагрузку прямых ссылок, обе темы, узкий экран и управление клавиатурой.
