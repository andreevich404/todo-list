# todo-list

Приложение To-Do List (лабораторная работа №7): To-Do на Vue 3 и Vite из лабораторной №6, расширенный Pinia, Vue Router и учебной авторизацией.

**Опубликованное приложение:** https://andreevich404.github.io/todo-list/

> **Авторизация учебная.** Сервера нет: аккаунты и вход существуют только в `localStorage` вашего браузера и видны через DevTools. Для проверки используйте **только вымышленные адреса и учебные пароли**, которые нигде больше не применяются.

## Возможности

- четыре страницы: регистрация, вход, задачи, «О приложении»; страница задач закрыта для гостей;
- у каждого пользователя свой список задач, выход не удаляет аккаунты и задачи;
- добавление, редактирование и удаление задач через нативное модальное окно `<dialog>`;
- отметка выполнения: выполненные задачи зачёркиваются, получают галочку и уходят вниз списка;
- поиск по названию с фильтрацией по мере ввода;
- светлая и тёмная темы (выбор сохраняется, при первом визите учитывается `prefers-color-scheme`);
- хранение через `pinia-plugin-persistedstate` в `localStorage` (`todo.users`, `todo.store`); повреждённое хранилище не ломает запуск;
- адаптивная вёрстка, отключение анимаций при `prefers-reduced-motion`, озвучивание действий через `aria-live`.

```bash

```

## Pinia и сохранение данных

- `useUserStore` — `users` (id, email, соль, число итераций и хеш пароля), `currentUserId`; действия `register`, `login`, `logout`; геттеры `currentUser`, `isAuthenticated`.
- `useTodoStore` — `tasks` (каждая задача хранит `userId`), `nextId`; действия `add`, `rename`, `toggle`, `remove` работают только с задачами владельца; геттер `forUser(userId)` отдаёт список с выполненными внизу.
- Страницы не хранят копий данных, а читают сторы. Плагин `pinia-plugin-persistedstate` сохраняет `users` и `currentUserId` в ключ `todo.users`, а `tasks` и `nextId` — в `todo.store`. После обновления страницы вход и задачи восстанавливаются; `logout` сбрасывает только `currentUserId`.
- После восстановления вызывается `sanitize`: повреждённые или правленные вручную записи отбрасываются.
- Пароль хранится как PBKDF2-SHA256 (600 000 итераций, соль у каждого пользователя), а не открытым текстом. Это не защита: без сервера любой может подобрать пароль или править `localStorage`. Старые задачи из лабы №6 (без владельца) не переносятся.

## Маршруты

| Путь | Страница | Доступ |
|---|---|---|
| `/#/login` | вход | только гостям |
| `/#/register` | регистрация | только гостям |
| `/#/todo` | задачи | только вошедшим |
| `/#/about` | о приложении | всем |

Guard в `router/index.js` перенаправляет гостя с `/todo` на вход (в `redirect` запоминается адрес) и вошедшего пользователя — со страниц входа и регистрации на `/todo`. Проверка срабатывает и при прямом открытии адреса, и при обновлении страницы. Используется `createWebHashHistory()`: GitHub Pages отдаёт только `index.html`, а адреса вида `/#/todo` открываются напрямую без настройки перенаправлений.

## Как проверить авторизацию

1. Открыть `/#/todo` без входа — произойдёт переход на страницу входа.
2. На странице регистрации отправить пустую форму, неверный email, короткий пароль и разные пароли — под полями появятся ошибки. Зарегистрироваться с вымышленным адресом, например `ivan@example.com`, и паролем `secret1` (учебным, нигде больше не применяемым). Повторная регистрация с тем же email даёт ошибку.
3. Войти: с неверным паролем появится ошибка, с верным откроется список задач. Добавить пару задач.
4. Нажать «Выйти», зарегистрировать и войти вторым пользователем, например `petr@example.com`: задач первого пользователя не видно. Добавить задачу.
5. Выйти и войти первым пользователем снова: видны только его задачи. Обновить страницу — вход и задачи сохраняются.

## Доступность

- нативные `<button>`, `<input>`, `<dialog>`, `<label>`; порядок Tab совпадает с порядком в DOM, `tabindex` не используется;
- кнопки-иконки называются вместе с задачей через `aria-labelledby`: «Удалить задачу Купить молоко»;
- в модальном окне фокус попадает в поле названия, Esc закрывает окно, при закрытии фокус возвращается на кнопку-инициатор;
- после удаления фокус переходит на ближайшую видимую задачу или на кнопку «Добавить задачу»; после переключения чекбокса фокус остаётся на нём;
- новые формы: у каждого поля есть `<label>`, ошибки показываются под полем с `role="alert"` и связаны через `aria-describedby`, фокус переходит на первое поле с ошибкой;
- навигация в `<nav aria-label>`, ссылка «К содержимому», после перехода между страницами фокус уходит на содержимое;
- видимый `:focus-visible`, контраст текста не ниже 4.5:1 в обеих темах.

## Публикация

Хостинг — **GitHub Pages**. Workflow `.github/workflows/ci.yaml` при пуше в ветки `lab-6` и `lab-7` (или вручную) выполняет `npm ci`, `npm test`, `npm run build` и публикует содержимое `dist/` через `actions/deploy-pages`. Роутер работает в hash-режиме, а в `vite.config.js` задан `base: './'`, поэтому сборка работает по адресу вида `https://<пользователь>.github.io/todo-list/`. В настройках репозитория: **Settings → Pages → Source: GitHub Actions**. Ветку, из которой разрешён деплой, нужно добавить в **Settings → Environments → github-pages → Deployment branches**; после слияния PR ветку в workflow нужно заменить на `main`.
